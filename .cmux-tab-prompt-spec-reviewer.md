## Problem

The skill's per-task pipeline always runs three phases (implementer → spec-reviewer → code-reviewer). For trivial changes — small test-only diffs, doc/typo fixes, single-line config tweaks — the code-quality review adds wall-time and tokens with near-zero signal.

## Goal

Document a planner-side heuristic for safely skipping the code-quality review on trivial diffs, and add a small helper script the planner can call to make the decision deterministic.

## Approach

1. Add `skills/cmux-tab-agents/references/skip-heuristics.md` describing when it is safe to skip the code-reviewer phase. Heuristic (as a starting point — implementer may refine):
   - `git diff --shortstat <implementer-sha>~1..<implementer-sha>` shows ≤ 30 changed lines, AND
   - All changed files match `*test*` / `*spec*` patterns OR are pure markdown OR are the changelog, AND
   - Spec-reviewer reported `APPROVED` with no concerns flagged.
   If all three hold, the planner MAY skip code-reviewer dispatch and mark the sub-task done.
2. Add a helper script `skills/cmux-tab-agents/scripts/should-skip-code-review.sh` that:
   - Takes `--worktree` and `--implementer-sha` arguments.
   - Inspects the diff and the spec-reviewer result file.
   - Exits 0 if skipping is safe, 1 if not, with a one-line reason on stderr.
3. Update `SKILL.md` "Per-task pipeline" section with a brief note pointing at the heuristic and the helper. Make clear the planner is NEVER required to skip — this is opt-in optimization.
4. Make sure the heuristic is conservative — when in doubt, do not skip.

## Hook-bypass check

In addition to verifying the spec, **scan the implementer's commits for hook bypass**:

```bash
git log <base>..HEAD --pretty=format:'%H %s'
git log <base>..HEAD --grep='no-verify' -i
```

Watch for:
- Commit messages mentioning `--no-verify`, `skip hooks`, `bypass hooks`, `husky=0`
- Suspicious split commits (e.g., one commit adding a file, immediately followed by a commit modifying it in a way that should have failed the hook)
- Modified hook scripts in `.husky/`, `.git/hooks/`, `lefthook.yml`, etc.
- Suspiciously fast commit cadence on a repo known to have slow hooks

If you find evidence of hook bypass, the result is `ISSUES_FOUND` regardless of spec compliance. Call it out clearly so the planner re-dispatches the implementer with explicit "fix the hook, do not bypass it" instructions.
